# Bounded Spec001 observation contract

`scripts/remediation-acceptance.py` validates complete per-criterion **untrusted local observations** and emits the Jest-compatible shape already consumed by the unchanged harness collector. SHA256 detects drift and source equivalence; it does not authenticate an author, GitHub response, approval or independent review. This runner grants no merge authority and changes no factory configuration.

Run `python3 scripts/test-remediation-acceptance.py` for small offline contract fixtures. Run the observation validator with `--observations <manifest.json> --output <results.json>`. Exit1 means at least one criterion is incomplete; eight real passed/failed assertions are emitted, never skipped-as-passed. The default root is this repository; `--root` supports disposable contract fixtures. Do not pass synthetic test records as application evidence.

The manifest requires schema_version1, candidate_sha, baseline_sha (the approved original930c7e8), complete source_sha256 mapping, and criteria AC-1 through AC-8. Source hashes bind the committed candidate and tracked current runtime/application/workflow/spec source. Untracked source, missing paths and working-copy drift reject every criterion. Subsequent proof/documentation-only commits can reuse a candidate only when this full source scope is unchanged; that is source-equivalent proof, not a fresh exact-head run. Each command record separately binds the complete application scope, its observed immutable Git commit, exact argv, exit and hash-bound raw log. The observed commit manifest is derived from Git, never accepted merely from caller hashes. Historical observations must be explicitly marked historical-source-equivalent. File artifacts are bounded to2MB under verify/ or docs/; external/symlink paths and hash drift reject.

- AC1 requires a complete audit on the exact application scope. This local qualifier conservatively also leaves moderate findings pending; it does not approve any residual severity. Residual findings remain pending: this version has no authenticated residual-risk decision adapter. A supplied approval boolean cannot accept them.
- AC2 checks exact package/lock hashes from the approved migration against the recorded approval artifact, plus the complete captured native baseline run/jobs on immutable source-equivalent runtime/application/helper bytes and successful clean npmci steps.
- AC3 requires noninteractive lint, actual seeded lint rejection, typecheck, the complete original unit suite, coverage thresholds and a conservative per-file lexical assertion-count tripwire for baseline src/ and e2e/ tests, rejection of newly introduced skip/focus controls, and unchanged strictness. This is not an AST or semantic proof that individual assertions are unchanged; actual suites and review remain necessary.
- AC4 requires captured baseline jobs on source-equivalent complete runtime/application/helper bytes, current-major successful build output, the existing public font connectivity route and separately retained original offline failure.
- AC5 requires both desktop/mobile projects and all stated browser behaviors, the complete applicable run, and all seven actual local database HTTP/SQL/RLS observations. Database equivalence is derived from its observed Git commit across the route, imported database types, unchanged migration, package/lock and Next/TypeScript startup configuration; the committed test harness and retained result/observation must also agree. New local runtime imports require closure review. Historical local database evidence stays explicitly local and source-equivalent; hosted behavior is unproven.
- AC6 **always remains failed in this version**. The authenticated exact-candidate independent code/security-review adapter is not configured. Caller booleans, local review text and supplied native JSON cannot confer independent or current-head review credit. This conservative limit is explicit, not an alternative acceptance policy.
- AC7 requires an explanation for every baseline-to-candidate application change, the same lexical assertion-count/skip tripwires and strictness, unchanged database files and no introduced service-role use.
- AC8 checks baseline/final audit records and accurate disclosure of current collector counts/verdict, remaining low findings and pending native limits. Reporting an incomplete gate honestly is distinct from passing that gate.

Do not fabricate labels in unit tests, amend criteria, edit producer gates or grant readiness to make the count green. The native comparison includes all code/workflow source excluding only this standalone validator and its fixture script, which the unchanged baseline does not execute. Unknown execution of those scripts blocks reuse. Native captures are retained supplied observations, not authenticated receipts; exact source IDs/run attempts and historical limits must remain visible. A later approved authenticated adapter is required before full Spec001 can be claimed complete.

Malformed top-level/nested observation shapes produce eight failed assertions. The CLI atomically replaces output with a fresh incomplete result before parsing/evaluation, so malformed input cannot leave an older passing result at that output path.
